# 决策创建、修订与失败恢复

对应 F09 / US08、P07 / P12、AC07，以及 AC15 在决策表单中的失败反馈。
依据 01-product-baseline.md 的不可变修订/依据快照规则和 04-api-contract.md
的幂等、人工合并协议。本轮没有改变 API schema、数据库模型或迁移。

## 用户可观察的行为

| 情况 | 页面行为 | 后续动作 |
| --- | --- | --- |
| 等待写入 | 冻结输入及依据勾选，同步阻挡重复提交 | 可关闭窗口，操作仍可完成 |
| 网络失败、5xx、响应丢失、30 秒等待超时 | 标为未确认，保留原键/路径/正文/预期修订 | 仅重试原请求；不生成新键或反复追加修订 |
| 明确的参数、权限、来源不可用等拒绝 | 保留可编辑输入；失败事务未占用键时复用原键修正 | 如 422 空理由，或 404 笔记已回收，可修正后再保存 |
| 409 VERSION_CONFLICT | 保留本地输入，读取服务器标题/类型/理由/方案及依据数量 | 比较并手动合并，明确采用服务器修订后才允许新的提交 |
| 冲突读取失败 | 展示读取错误，继续禁止保存 | 只读重试；不能跳过比较 |
| 明确采用后服务器又更新 | 再次 409，继续保留输入 | 再次比较，不自动覆盖 |
| 收到成功回执 | 确认对应修订，关闭表单，提供该修订链接 | 后台列表/详情刷新独立进行 |
| 成功后的读取失败 | 保留成功提示与已读取的详情，单独显示读取失败 | 重试只做 GET，不再 POST |

新建与修订共用 DecisionDialog；旧调用入口 DecisionEditor 保留为导出适配。
线索创建入口不再逐次生成新 UUID。修订入口不再因为正文变化就自动换键，
也不会把保存后的回调读取异常当成写入失败。明确接受冲突修订后属于一次新的
用户提交意图，使用新键和新的 expected_revision；它不是原请求的网络重试。

已确认的原回执可能是 v2，而当前决策已被其他请求推进到 v3。此时重试只确认
原 v2，不声称它仍是最新，也不追加 v4。历史和任务 source_revision_no 不被更改。

## 依据与生命周期

依据使用受控 ID 集合，三类分别最多 100 项。选中后翻页、重新读取、关闭/重开
窗口，不会自动取消勾选；从列表消失的已选来源仍明确保留，用户可在明确拒绝后
移除。初次读取失败与“没有可选记录”分开显示，分页失败可重试。

选择时显示的摘要用于帮助识别来源。历史快照由服务器在**首次成功提交时**逐个
授权并锁定来源后生成；它不是浏览器打开表单时的冻结版本。若首次事务未提交，
后续首次成功写入会采用当时的合法来源状态。若已提交但回执丢失，同键重试返回
原回执，不重新生成快照，即使笔记后来已编辑/回收、假设已修改也如此。

草稿和未确认操作只保存在当前组件内存中；关闭/重开同页窗口保留它们，页面
卸载、刷新、退出后的持久恢复尚未实现。服务端普通幂等记录保留一天，客户端
23 小时后拒绝重放未确认请求，提示先核对历史。该等待时限不是服务端事务撤销，
也不是跨设备持久化保证。任务和决策现共用 30 秒请求等待及重试时限常量。

## 实际证据

`backend/tests/test_decision_replay.py` 使用真实 PostgreSQL，定向 **4 项通过
（7.75 秒）**：依据修改/回收后创建回执与原快照一致；追加更高修订后旧回执不
重建快照/不追加；三路同键并发只产生一个修订/事件；失败键回滚、已接受键不能
改正文或跨空间取回结果。原先的历史不可写/不同键版本竞争测试继续保留。

`frontend/e2e/decision-state.spec.ts` 新增 **8 条真实浏览器用例，定向通过
（32.1 秒）**。网络失响应用 route.fetch() 先让真实事务提交，再中断或暂扣浏览器
响应；检查数据库历史/快照/事件与请求键/正文，并包含后页笔记选择、连续冲突、
成功后读取故障。最后一条推进浏览器时钟实测 30 秒等待超时及 23 小时重试守卫，
没有假称服务器撤销已完成事务。类型检查发现的表单 DOM 类型标注和重复 key
属性已修正；未降低任何验收断言。完整回归最终结果见实施状态及进展记录。

完整后端 **168 项通过（466.30 秒）**。首次全套浏览器 24 通过 / 1 失败，原因是
新组件改变了原有分页按钮名称；已恢复原应用按钮名称，保留既有分页用例。
失败 JSON/HTML/trace 存于 `artifacts/decision-state-initial/`；定向成功报告存于
`artifacts/decision-state-focused/`。恢复标签后重新构建/重启并运行完整浏览器，
最终结果另记。

最终完整浏览器 **25 条通过（121.99 秒）**，包含原先 17 条及新增 8 条；无跳过、
意外失败或 flaky 结果。标签恢复后前端类型、生产构建、重启均通过；25 项依赖
工具、3 项公式安全、依赖清单/版本、lint、契约、迁移/日志/消息检查也通过。
后端在全量通过后没有修改，未为前端标签修正重复运行。独立最终报告目录与
源码提交摘要绑定于 `artifacts/decision-state-milestone.json`。冲突窗口的桌面和
390px 图已目视检查，移动窗口内容没有横向溢出。

桌面和 390px 冲突窗口截图及宽度检查覆盖基本布局，不替代完整键盘/读屏、
跨浏览器、真机、负载或全部页面状态验收。其他通用 FormDialog 创建/更新入口
仍须逐一审查，不能从这一组件推导全产品安全重试完成。完整发布门禁仍开放。
