# 任务页面筛选与失败恢复

对应 F10 / US09、P07 / P13、AC08 / AC09，并补充 AC15 在任务入口的验收。
本轮范围为任务列表、首页/线索任务状态操作、任务详情及普通/决策来源创建。
这份记录不关闭其他页面或企业发布门禁。

## 查询与页面行为

`GET /api/v1/tasks` 支持可组合的 `project_id`、`thread_id`、`status`、
`priority`、`due_from`、`due_to`。状态为 todo/doing/done/blocked；优先级为
low/medium/high。日期是 DATE，无时区换算，两端包含；任一日期界限存在时，
没有截止日期的记录不匹配。逆序日期和非法值返回 422。

归属和全部筛选先于数据库分页，排序仍为 created_at DESC / id DESC。
游标绑定空间、父对象和全部规范化筛选；换条件不能沿用旧游标。部署后旧版
任务游标失效，客户端应刷新第一页。分页仍不承诺跨请求一致性快照。

任务页默认显示当前课题，可切换所有课题；切换具体课题沿用页面顶栏选择器。
状态/优先级/截止日期/范围写入 URL，刷新和浏览器返回恢复条件。无当前课题时
明确提示选择/创建，不会把“当前课题”解释为所有课题。查询失败与筛选无结果
分别展示；后页或后台刷新失败保留已加载记录，提供原页重试。

## 保存与冲突

- 状态按钮保留一次操作的 ID、expected_version 和目标状态。等待期间禁用重复
  点击，失败显示在对应任务旁；重试复用原内容，不根据可能刷新的状态再次切换。
  409 必须先读取最新状态，之后由用户决定是否进行新的操作。
- 只有写入响应或显式读取确认后才更新已知实体；后台列表刷新独立进行，不让
  一个未返回的刷新请求卡住已成功写入的按钮。刷新失败保留已知最新版本。
  创建重试会返回原始回执；若缓存已确认更高任务版本，不能被旧回执降级。
- 两种创建入口均保留幂等键、请求正文和目标路径。等待期间冻结字段；结果
  未确认时保留并冻结表单，提供“重试原请求”。同一已挂载页面内关闭/重开弹窗
  保留原操作。服务端幂等记录保留一天，客户端在 23 小时后拒绝重放不确定创建，
  提示先核对任务列表。该状态不跨刷新/退出/页面卸载持久化；不能宣称离线恢复。
- 决策创建入口在打开表单时固定决策修订。即使原决策随后追加修订，未确认
  请求仍使用原路径/正文/幂等键，不能静默改绑新修订。
- 编辑窗口保留打开时版本和受控字段。409 后只读取得服务器版本并展示差异，
  保留本页输入；用户手动合并并明确确认后，才允许基于新版本再保存。第二次
  并发更新仍由服务端版本校验拒绝，不自动覆盖。
- 任务写入/冲突读取有 30 秒客户端等待上限；超时表示结果未确认，不能当失败
  已回滚。客户端超时不承诺中止服务器事务。未引入任务来源修改或历史覆盖接口。

## 可重复验证与边界

`backend/tests/test_task_filters.py` 使用实际 PostgreSQL：43 条匹配记录具有相同
时间戳，较新的非匹配任务不能遮蔽旧结果；组合日期含边界、无日期、父对象、
其他空间、查询游标错配和非法值均有断言。定向 6 项通过，报告
`artifacts/task-filters-focused.xml`。

`frontend/e2e/task-state.spec.ts` 使用真实账户/数据库及浏览器网络故障注入：后页
失败与保留/重试、初次读取失败、URL 条件、普通写入失败、实际已提交但响应丢失、
同键创建重试、人工处理编辑冲突，以及决策推进后的旧修订重试。网络故障通过
`route.fetch()` 让真实事务提交后再中断浏览器响应，不把纯模拟响应当成保存证明。

首次 6 条浏览器用例为 3 通过 / 3 失败，失败来自选择器同时选中 Next.js 路由
播报器和业务警报，随后将断言限定到 main；该版本的 6 条用例全通过（25.7 秒）。
原始错误和 trace 保留在 `artifacts/task-state-initial/`。新增决策入口与时限守卫后
的最终结果另行记录，不能沿用该中间结果。

后续全套浏览器两次为 16 通过 / 1 失败，均来自既有 research-core 用例用宽泛
文本定位同时匹配决策标题与关闭的任务弹窗出处文本（创建后、刷新后各一处）。
改用精确 heading 角色定位，保留完整断言；报告分别留在
`artifacts/task-state-unified-initial/` 与 `artifacts/task-state-cache-initial/`。
同时增加“创建回执重放前已完成任务”的组合断言，暂停详情读取时也必须保留
已确认的 v2，不能退回原始 v1。最终完整结果另见实施状态。

最终全量后端 **164 项通过（408.72 秒）**；前端最后构建/类型检查/重启后，完整
浏览器 **17 条通过（约 1.6 分钟，其中 8 条为新增任务用例）**。另有 25 项依赖工具
与 3 项公式检查、契约/迁移等本地门禁通过。由于统一脚本的初次浏览器阶段因
选择器失败退出，后续只重跑发生变化的前端检查与完整浏览器集合；后端无追加
修改，未重复运行。机器可读 XML/浏览器 JSON、失败报告、截图与源文件摘要记录于
`artifacts/task-state-milestone.json` 及其引用的独立报告目录。

当前只验证本机 Chromium 与小数据集。手机宽度截图只检查任务页面基本布局；
不代表真机、键盘/读屏、跨浏览器、整体 WCAG 或生产查询容量验收完成。任务页的
请求状态改进不自动覆盖其他模块的创建表单。生产平台、日志新鲜 witness、备份
故障域、部署/SMTP/用户试用等原有门禁继续保留。
