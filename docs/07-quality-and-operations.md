# 测试、发布与运行方案

所有阈值是拟定验收目标，测试尚未执行。S0 固定容量、样本和环境；报告必须能复现，不能把设计门槛写成实际达标结果。

## 拟定容量与非功能目标

| 项目 | 目标和测试边界 |
| --- | --- |
| API 延迟 | 常规列表 P95 ≤800ms（S1）；拟定 50 并发用户、稳定 20 req/s、运行 15 分钟，真实字段/权限/分页 |
| 页面 | 首次常规页面可交互 ≤3s（S1）；固定 1366×768 设备和网络，报告浏览器版本及缓存状态 |
| 搜索 | 拟定 P95 ≤1s；每空间 500 论文/5000 证据/1000 笔记，中文短词单测 |
| PDF | 起点 50 MiB/500 页；正常样本按 5/50/200 页分桶；后台解析与文件阅读互不阻塞 |
| 任务 | 初始 parse timeout 120s、3 次尝试；按页数/文件类型样本校准；超限明确失败可人工处理 |
| 笔记 | 停止输入约 1s 自动提交；确认保存响应拟定 P95 ≤800ms，断网不伪报成功 |
| 导出 | 初始 2 GiB 空间档案建议 10 分钟内完成；超过限制明确反馈；全量 checksum/关系校验 |
| 服务 | 小范围试用拟定月度可用率 99.5%，不对外宣称 SLA；依实际运行和人员能力调整 |
| 恢复 | 拟定 RPO ≤24h、RTO ≤4h；需覆盖 DB + 原文件，实测不达标则调整方案或目标 |

所有数字是验收候选值；S0 记录最终版本。压测分别报告 API 等待、队列等待、解析/打包时长、传输时长和资源峰值，不能用单一“完成时间”掩盖慢队列或网络。满文件/无文本/损坏文件也须测试资源限制。

## CI/CD 与迁移发布

每个 PR：格式/lint/typecheck → 必要单元测试 → PostgreSQL 迁移与集成 → OpenAPI 差异/前端生成类型 drift → 关键 E2E → 依赖与秘密扫描。输出报告与工单链接。CI 使用独立测试数据库与最小权限应用角色，不用数据库 owner 运行权限测试。

合并后生成不可变 Web/API/Worker 镜像、SBOM/依赖清单和 release manifest，部署 staging；用新建和有历史数据的两种数据库演练 upgrade。生产迁移由单独 runner 执行，不让多个 API 副本启动时竞跑迁移。

生产 schema 采用 expand/migrate/contract：先兼容扩展 → 应用兼容新旧字段 → 回填和验证 → 下一版收缩。为大索引和回填评估锁、超时、批量大小与维护窗口。破坏性迁移不用 downgrade 当唯一恢复方案，必须有备份与前向修复材料。

回滚默认回退应用镜像，要求数据库仍兼容上一版；有不可逆数据损失时进入恢复流程，不自动执行删除列/历史表。队列任务带 schema/worker 版本，旧 Worker 不处理不兼容任务，滚动升级前验证消费兼容。

## 备份、隐私与删除

数据库每日加密备份，原始对象按版本保留且防覆盖，备份集合记录 DB 时间/存储清单/摘要；月度恢复演练和发布前演练都在隔离环境开展。仅数据库备份不能恢复论文，因此演练同时验证旧文件、证据跳转、决策历史和笔记。拟定 30 天滚动保留需项目负责人批准，并与用户说明一致。

应用日志只含 request_id、route template、耗时、错误码和内部对象 ID；不含密码、会话、签名 URL、论文正文、私密研究文本。建议运行日志 14 天、匿名指标 90 天为起点；科研活动历史随空间保留，不当通用运行日志过期清理。管理员读取资料需受控、留审计记录；MVP 无默认第三方 AI 传输。

删除预览检查证据/修订/任务/导出和原文件依赖。归档不清理；笔记软删提供恢复窗口；原 PDF 正被历史引用时普通操作返回依赖冲突。全账户删除按受控服务顺序清理并追踪失败；备份过期前明确“在线删除已完成，备份按政策过期”，不显示虚假的即时物理清除。恢复前重放独立删除账本。

## 可观测性与故障手册

| 信号 | 初始告警条件 | 处置 |
| --- | --- | --- |
| API 5xx | >1% 持续 5 分钟 | 关联发布版本与 request_id；必要时回退镜像 |
| 队列最老任务 | 排队 >5 分钟 | 查 Redis/Dispatcher/Worker；从 outbox 重发，不手工标 succeeded |
| Worker 租约 | 过期未回收 | 回收服务告警；根据 attempt_token 安全重试 |
| 数据库连接/磁盘 | 使用 >80% | 限制并发导出、调整池/容量，分析慢查询 |
| 来源不可用 | 新增 unresolved 或文件摘要异常 | 保留异常对象，冻结替换/清理，检查存储版本 |
| 备份 | 连续一次计划备份失败 | 修复并补备份，确认最后可恢复集合 |
| 导出失败率 | >5%（有足够样本时） | 核对文件与快照；明确失败，禁止提供残缺成功包 |

运行手册至少包含：会话撤销、Redis 停机、Worker 卡住、对象存储不可用、迁移失败、PDF 摘录错位、笔记冲突、备份恢复、数据泄露、受控删除重试。每份手册注明主责/代理、诊断步骤、变更操作、回滚及用户影响；低样本告警结合绝对错误数，避免百分比误报。

## 发布门槛与试用顺序

以下全部达标才能核准具体 RC：F01–F15 与 AC01–AC15 有验收记录；13 步核心流程可独立执行；TC/DB 及高风险 T 用例通过；双用户隔离无泄漏；原文来源和全部历史可靠；笔记无静默丢失；导出结构与文件完整；备份恢复实际执行；SLO 容量测试、桌面兼容性、监控和值班准备完成。

阻断级/高严重缺陷为零；中低缺陷有清楚影响和负责人。发布记录列出镜像 digest、迁移版本、批准者、时间、已知问题和恢复点。

先内部合成数据验收，再 5–8 人受邀试用；运行和资料保护稳定后进入 30–50 人四周试用。遇到越权、错来源、历史覆盖或静默丢失立即停止扩大用户、保护证据并修复；必要时冻结受影响写入。用试用指标与任务观察决定后续 P1，不能只看页面访问量。
