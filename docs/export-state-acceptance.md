# 导出请求恢复与结构化档案验收

日期：2026-10-16。对应 F15 / AC13，以及贯穿页面失败与重试的 AC15。
范围仍覆盖完整 P0 和企业发布门禁；本文件仅记录本轮实现和直接证据。

## 已复现的问题

旧 data-settings.tsx 在每次点击时生成新键，且创建任务与列表刷新处于同一个
错误处理段。真实 HTTP/队列用例让第一次提交在服务器成功后丢失回执，再等待
档案完成；用户重试后出现不同请求键和第二个 job ID。失败报告和 trace 保留
`artifacts/export-state-before/`，不是只凭代码审查推测风险。

进一步用真实 PostgreSQL/私有对象存储验证：被证据引用的文件标为 missing 时，
原来连 include_files=false 也失败。`artifacts/export-records-only-before.xml`
保留了此断言失败；包含原件导出失败是正确行为，结构化档案不能据此被一并阻断。

## 用户操作与恢复记录

- 创建前先保存原 include_files、请求键、创建时间和空间；结果未知时选项冻结，
  重试沿用原键/正文。原任务已经完成也不能因此把重试当作新的档案。
- 202 只确认请求已接收。任务状态使用独立 GET；历史 queued 回执不覆盖当前
  已完成/失败/过期状态。已确认接收后的列表、详情或本机存储失败不撤销回执。
- 原请求确认后，用户必须明确点击“开始新的导出”；客户端再读原任务，读取
  成功且原任务已终止才解锁下一次选项。读取失败保留原请求。
- EXPORT_IN_PROGRESS 是明确未创建本次任务的拒绝；原键未被消耗，用户可原键
  重试，或明确修改选项开始新意图。未确认请求不能通过普通按钮自动换键。
- 每个同源空间保留一条 `researchos.<workspace_id>.export` 记录。只有版本、
  空间、键、时间、布尔选项、阶段、job ID 或明确拒绝码，不存密码、下载地址、
  文件或科研正文。字段白名单、长度、UUID 和阶段关联校验失败时阻止自动写入。
- 同步 busy 守卫和 Web Locks 串行处理同源同空间的操作；跨标签页读取存储变更。
  退出登录、账户删除沿用空间前缀清理，迟到的请求/下载核对不会重建记录或导航。
- 显式清除只影响本机记录；页面说明不会取消后台任务或删除原档案，并要求先
  核对已有导出。清除浏览器数据、另一设备或 23 小时之后的未知请求不承诺自动恢复。

JSON 等待上限为 30 秒；23 小时守卫依据本机时间，为服务端一天的幂等保留期
留出余量。记录时间明显晚于当前时钟时也拒绝读取，避免时钟回退被当成新请求。
这不是可信时钟、跨设备协调或无限保留协议；不支持 Web Locks 时明确阻止提交。

已缓存任务也必须与恢复记录的空间、job ID 和 include_files 一致，才用于原请求
状态和下载入口。新增用例合成了语法合法、选项却被改变的浏览器记录：修复前
旧缓存仍显示原请求的下载按钮；修复后停止使用该缓存，人工读取明确提示不一致，
不创建新任务。服务器真实导出列表仍可用于人工核对，不能把局部异常当作新的请求。

## 原件不可用时的明确选择

Worker 仍对 include_files=true 的被引用不可用原件返回
EXPORT_REQUIRED_FILE_UNAVAILABLE，不能产生完整成功档案。用户明确选择
include_files=false 后，导出实体、关系、历史和笔记，保留原 paper_file_id、
摘要及 availability_status；ZIP 不含原件，manifest.include_files=false、files=[]，
missing_files 对该源标为 referenced_version_unavailable。没有改写证据出处，
也没有把缺失原件宣称已包含。未引用的移除版本保留原有 unreferenced_version_removed。

失败原因采用可理解的中文说明；仍在重试的 queued/running 与终止 failed 分开
显示，不把一次失败尝试误报为最终失败。manifest 仍为 schema_version=1，新增
缺失原因是已有 missing_files 列表的补充；现有档案结构验证器也检查这种记录档案。
本轮没有 ORM、数据库迁移或公开 DTO 变化。

## 下载与边界

下载前重新授权读取原任务、核对状态和到期时间。二进制 GET 仍由服务端重新
授权；浏览器使用原生附件下载，不在 React 中将大档案收为 Blob。
下载状态核对与实际 GET 之间仍可能过期或失败，失败响应在原页反馈并保留
已确认的导出意图。页面只显示“已请求下载，请在浏览器下载记录中确认结果”，
不把接收回执或发起下载当成文件已经完整保存。

原生下载样本实际保存到项目 artifacts/downloads；检查整个 ZIP 的 SHA-256
与响应头/任务摘要一致，解包验证 manifest、原 PDF 字节摘要与文件 ID，并检查
档案不含 password_hash/auth_sessions。另一个用例验证仅结构化档案的证据关系、
缺失标记和没有 PDF 字节。大档案、传输中断、断点续传和全部浏览器仍需单独验收。
