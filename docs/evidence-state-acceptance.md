# PDF 摘录出处与失败恢复

对应 F05–F07 / P07 / P09、AC04 / AC05 / AC14，以及 AC15 的读取/保存失败状态。
按产品基线保留原文、解释、线索、确切文件版本与页码；本轮不改变 API、ORM 或迁移。

## 出处不随阅读位置改变

PDF 文档实例随实际文件 ID/读取地址重建，不能只依据 paperId 或 URL 中是否有
fileId 判断。翻页/缩放采用独立画布和文字层，所有异步步骤检查取消状态；只有
完成渲染的页能提供摘录上下文。旧页面文本任务不能在清理后填入新页面。

摘录草稿保存文件 ID/版本、页码、原文、解释、捕获方式/坐标及所选线索。手动
修改原文会明确降为人工录入，但不自动改绑当前阅读页。翻页、缩放、切换同一
文献的文件版本、切换顶栏课题，不会重写草稿出处；切换后的新选文也不能覆盖
正在保存、结果未确认或已确认的记录。界面保留原线索选项，并说明出处仍为原页。

成功后锁定本条表单，按服务器回执的 thread_id 跳回原线索；可到证据详情修改
解释。要形成新的摘录，明确选择“继续摘录下一条证据”。新草稿可重新选取当前
文件/页的原文，使用新的请求键。成功记录本身不在此表单中被改写。

上传完成接口只将验证/解析任务入队。版本列表已有的后台轮询在观察到当前文件
及其处理状态改变后，重新读取授权文件地址。首次刷新即使仍返回旧版本，后台
真正发布后也能刷新实际显示内容。显式指定历史 fileId 时仍读该历史文件。

## 失败与重试

| 情况 | 行为 |
| --- | --- |
| 等待写入 | 同步阻挡重复提交；冻结原文、解释、出处和线索 |
| 网络、5xx、30 秒等待超时 | 保留原路径/正文/幂等键；只提供原请求重试 |
| 明确拒绝，如空摘录 422、来源不可用 | 保留可编辑输入，未确认请求不会被静默换键 |
| 其他 PDF 文件读取失败 | 草稿组件仍挂载；原请求可独立重试，不依赖当前文件读取 |
| 写入成功后的后台读取失败 | 保留成功回执，读取重试只做 GET，不再创建 |
| 未确认操作超过 23 小时 | 停止重放，提示在原线索核对；不能假设服务器已回滚 |

服务端幂等键按空间/用户/操作/线索作用域隔离。同一键换到另一个线索能形成合法
的新操作，因此客户端必须同时保留原路径；单独复用键不足以防止错绑或额外记录。
结果未确认时，翻页或重新渲染只影响阅读状态，不能清除保存错误。

状态仅在当前阅读器组件内存中保存；同一文献的文件查询参数切换会保留，刷新、
退出、切换另一文献或页面卸载不承诺持久恢复。来源语义及定位级别仍由服务器
校验。手工摘录不冒充精确定位，原文件、已有决策快照和任务来源均未修改。

项目内缓存路径。不要将历史临时创建解释成“从未使用系统 TEMP”。
