**结果：[完整运行成功](https://github.com/Fancy8/ResearchOS/actions/runs/39583284264)。** 队列检查、后端、前端和浏览器门禁全部实际执行；没有降低断言、移除检查或把失败改成继续执行。

## 失败边界

旧工作流将环境/服务准备、浏览器安装、完整验证放在三个独立的 `run` 步骤。依赖工具、OpenAPI 和迁移检查通过后，后续步骤的队列状态读取返回 `BROKER_STATUS_UNAVAILABLE`，验证在后端与浏览器回归前退出。初始失败记录仍保留在 Actions 历史中。

## 修复

- 将准备、服务启动、浏览器安装和验证放在同一 PowerShell 会话中，使服务与消费者共用启动上下文。
- 安装后立即执行真实队列状态探针；原有验证中的同一检查继续保留。
- 增加有界 Redis 启停诊断，仅针对当前回环、无认证、合成数据的 CI Redis；不收集应用日志、环境文件或任务正文。
- 同一引用的后续验证取消过时运行，避免提交密集时重复执行。

新运行的两个 broker 探针均成功，然后执行了全部后续检查。这证明修正后的工作流通过了该托管环境；未进一步声称已经定位到 Windows 底层的具体进程终止信号或所有平台差异。
