## 差异审查与处理

| ID | 原文差异或缺口 | 本次设计处理 | 开发验证 |
| --- | --- | --- | --- |
| ADR-01 | S1 为 2–3 全栈、10–12 周；S2 为 4 开发加 QA、12–14 周 | 采用 S2 的 14 周容量窗口；小团队重新估算，不承诺沿用工期 | S0 拆任务，S2 后用真实吞吐预测 |
| ADR-02 | PRD 将文件字段放在 papers；S3 拆 paper_files | 采用 S3 物理模型；元数据与文件版本分开 | DB-04、DB-05、TC-005 |
| ADR-03 | S1 决策证据关系指向 decision；S3 指向 revision | 采用修订级快照；补齐关联假设和笔记快照 | 历史依据修改后旧修订仍一致 |
| ADR-04 | S2 证据请求没有 paper_file_id | 强制指定实际阅读版本；文件版本与论文一致校验 | 新旧 PDF 混用测试 |
| ADR-05 | S3 没有线索与假设完整修订表 | 新增 thread_revisions、hypothesis_revisions，记录问题和判断历史 | 修改问题/假设后能复盘原内容 |
| ADR-06 | S3 current_revision 没有指向真实修订的外键 | 增加延迟复合外键，提交时必须存在所指修订 | 伪造版本号数据库拒绝 |
| ADR-07 | 原任务关联决策但未固定任务产生时版本 | 增加 source_revision_no，关联确切修订 | 修订决策后任务仍能回看初始依据 |
| ADR-08 | 幂等表为未来预留；队列提交与 DB 提交分离 | 幂等记录、outbox、job lease 纳入 P0 生产支撑 | 超时重试、丢消息、Worker 中断 |
| ADR-09 | 上传完成缺少防覆盖与最终对象固定协议 | 上传到临时键，服务端复制到不可写最终键再验收 | 重放上传 URL 不改变已引用 PDF |
| ADR-10 | “导出可重建”与“一键恢复后续实现”容易混淆 | P0 包含可验证结构导出和内部重建校验；用户端一键导入是后续功能 | JSON 关系与 SHA-256 全量校验 |
| ADR-11 | BR04 允许其他原始记录；S3 evidence 必须 PDF | MVP 结构化 Evidence 仅支持 PDF 来源；其他记录先作为笔记，完整实验来源为 P1 | UI 清楚说明可支持来源范围 |
| ADR-12 | 科研画像更新有 PUT/PATCH 差异 | 统一 PATCH；笔记正文使用 PUT 完整保存 | 契约差异测试 |
| ADR-13 | 文件替换时旧定位状态表述不清 | 旧文件仍存在时旧证据正常定位该版本；仅无法获取/验证时降级 | 不误把“非当前版本”视为失效 |

ADR 为本次建议，不伪装为已批准决策。若评审改变 ADR，同步修改 API、模型、页面和验收，不让多份文件各自形成不同事实。
