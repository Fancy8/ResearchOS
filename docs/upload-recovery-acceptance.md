# PDF 上传恢复验收

日期：2026-10-16。对应 F05 / AC04、AC14；完整产品范围仍以产品基线为准。
本文件记录本地实现与实际测试边界，不能替代企业发布验收。

## 用户行为和状态

文献库和阅读器共用上传控件。选择时固定原文件名、大小、SHA-256、课题及目标
文献；以后切换顶栏课题、刷新或打开另一文件，不会重定向已经开始的上传。
大小范围为 1 字节至 50 MiB，服务端继续执行大小、PDF 标识、摘要、解析和归属校验。

| 阶段 | 持久信息与恢复动作 | 不确定结果的处理 |
| --- | --- | --- |
| preflight / duplicates | 保存意图，读取同摘要文件；新文献可复用确切历史版本，或明确保留独立记录 | 读取失败保留原意图；不自动跳过重复选择 |
| init | 固定初始化正文与 initKey，收到回执后保存 upload/paper/file ID | 同键重放；结果未知时不能用另一 PDF 替换 |
| transfer | 先读取原会话；pending 时传同一文件，validating/completed 跳过内容重传 | pending 不能证明服务端未收字节；只允许同摘要和大小的原 PDF 重传 |
| complete | 保存完成阶段及 completeKey，再发送原 upload_id | 刷新后无需重新持有 File 即可重放原完成请求 |
| accepted | 确认 202 回执，保存原 job ID；刷新列表和读取处理状态独立 | 读取失败不重新完成，不撤销已确认回执 |
| terminal | 明确失败或达到会话过期边界，保留原标识供核对 | 不自动分配新会话；用户明确重选 PDF 才开始新意图 |

“后台验证与解析已接收”只确认服务端接收完成请求，不代表验证或解析成功。
控件提供原文件版本跳转与只读状态查询。解析失败的再次执行由独立 ParseRetry
入口处理，上传恢复不会自动发起解析重试。

## 浏览器记录与并发边界

记录键为 `researchos.<workspace_id>.upload`，每个空间保留一个当前上传意图。
记录仅包含文件/课题描述、摘要、标识、阶段及幂等键，不保存 PDF 字节、Cookie、
密码、授权下载地址或服务器存储键。记录采用长度、字段白名单、类型、UUID 和
回执关联校验；损坏或不可写时阻断下一阶段写请求，保留人工核对入口。

刷新后浏览器不再持有 File。重新选取必须同时匹配原大小和 SHA-256；文件名
与目标仍使用原记录。初始化未知时先重放原初始化；收到原 ID 后才进入传输。
内容传输暂停/超时/异常保留结果未知，不声称已撤销服务端写入。

同源、同空间的操作由 Web Locks 排他串行；没有此能力的浏览器会明确阻止提交。
另一个标签页收到存储变更后读取新阶段，迟到的异步处理通过挂载代次检查阻断。
退出登录及账户删除沿用空间前缀清理；组件卸载后不重新创建恢复记录。
这不是跨设备恢复协议，也不宣称浏览器存储加密或完整 XSS 防护。

恢复记录保留至下一次明确上传、退出登录、账户删除或人工清除。清除入口明确
说明只影响本机记录，不取消服务端任务、不删除原件、不释放上传额度。
JSON 请求等待上限为 30 秒，XHR 传输为 10 分钟，并可暂停。客户端依据本机时间
执行 23 小时重放守卫，服务端回执保留一天；这不是可信时钟或无限期恢复保证。
会话有效期仍为一小时，以服务端拒绝和状态为准。跨设备、存储被清除和超过恢复
时限的未知初始化仍需人工核对文献库，不自动建立另一条记录。

已经收到 202、但本地 accepted 记录保存失败时，当前组件仍保留已知成功；只读
核对可再次保存该回执。刷新后只能读取到旧 complete 阶段时，仍使用原完成键确认。
列表/阅读地址刷新错误与写入错误分开；不会为了刷新重新上传。

## 后端完成请求边界

queue_upload_validation 原来只查询 queued/running/succeeded 的任务，导致失败任务
被排除、后续完成请求隐式新增任务；还会将原 processing 状态改回 queued。
现在查找原文件的既有任务，保留实际状态，仅首次创建任务时设置排队状态。
已确认上传却缺失任务记录时返回 STATE_CONFLICT，不自动补建任务。
同键幂等回执继续保持原响应；不同完成键的并发也只创建一个任务。
没有改动 ORM、数据库迁移或公开响应 schema。
