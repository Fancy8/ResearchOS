# ResearchOS 路线图

[首页](../README.md) · [实现进展](implementation-status.md) · [验收进度](acceptance-progress.md)

本页概述贡献方向，不承诺时间表。设计文档中的目标、实现记录中的已验证里程碑和未来计划需要分别阅读。当前为 Alpha，P0 仍按 F01–F15 / AC01–AC15 完整验收。

## 当前基础：已有实现与局部验证

课题、线索、PDF 来源、证据、假设、不可变决策修订、任务、笔记、搜索、活动记录与导出已进入实现。创建、上传、导出等已有故障恢复机制；对象授权、关系约束和历史语义贯穿业务。具体证据及未覆盖情形见[实现进展](implementation-status.md)。

## 第一阶段：完成 Alpha 体验与可复现维护

| 工作方向 | 需要交付的证据 | 可参与方式 |
| --- | --- | --- |
| 完整页面和失败状态 | 关联 F/AC 的验收记录与可复现用例 | 报告具体操作、预期和结果 |
| 多标签与晚到结果 | 竞争、关闭、退出后的回执等专门用例 | 使用合成数据补充故障测试 |
| 恢复草稿与兼容 | 损坏/过期记录、更多 PDF 和无障碍检查 | 提交可公开许可的合成样本 |
| 公开 CI 与干净环境 | 托管环境通过记录和安装复现 | 先排查真实失败，不降低安全校验来换绿灯 |
| 贡献者体验 | 与实际代码一致的指南、契约和英语文档 | 文档与翻译 PR |

## 第二阶段：验证可发布与运维边界

- 生产运行平台、Worker 支持方式与完整操作系统隔离。
- 大规模导出、数据库/对象容量与性能，实测恢复目标。
- 独立恢复见证、离机运行、旧写入者隔离与管理员边界。
- 备份密钥托管、调度和保留期，以及真实邮件提供商验证。
- 依赖、解释器和服务二进制审查；真实用户试用与最终发布审计。

正式备份调度和生产部署不因发布源码而自动启用，也不因小样本恢复实验而视为通过。

## 后续范围：先验证需求，再评审扩展

| 方向 | 前提 |
| --- | --- |
| 限定资料范围的 AI 问答与研究导航 | P0 用户验证，独立的数据授权、模型输入与评估设计 |
| 元数据、Zotero 导入与增量同步 | 明确来源许可、冲突语义和兼容维护成本 |
| 实验增强与写作工作台 | 明确用户任务与现有证据/修订关系 |
| 多人协作 | 新权限、成员和领域模型单独设计，不能直接沿用个人空间假设 |

批量 OCR、自主科研 Agent、自动实验执行和自动投稿不属于当前版本承诺。

## 如何提议优先级

具体问题提交到 [Issues](https://github.com/Fancy8/ResearchOS/issues)，工作流和方向讨论到 [Discussions](https://github.com/Fancy8/ResearchOS/discussions)。说明影响的任务、可复现情境与验收方式；维护者按实际需求和验证结果安排工作。这里没有固定响应 SLA。
